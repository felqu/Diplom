# Интеллектуальная платформа обучения и тестирования

Монорепозиторий микросервисной платформы для управления знаниями, генерации тестов с RAG, проведения аттестации и адаптивного обучения сотрудников.

## Границы сервисов

| Сервис | Ответственность |
| --- | --- |
| `identity-service` | Учётные записи, роли, права доступа и аудит действий. |
| `organization-service` | Подразделения, группы и связь сотрудников с ними. |
| `learning-service` | Учебные программы, курсы и материалы программ. |
| `knowledge-base-service` | Загрузка, категоризация, извлечение текста и поиск документов. |
| `ai-generation-service` | RAG-пайплайн и генерация вопросов/тестов через LLM. |
| `assessment-service` | Банк вопросов, конструктор тестов, импорт и экспорт. |
| `testing-service` | Назначения, попытки, ответы, оценивание и правила прохождения. |
| `proctoring-service` | Сбор событий клиента и обнаружение нарушений. |
| `adaptive-learning-service` | Рекомендации, анализ результатов и индивидуальные траектории. |
| `analytics-service` | Агрегаты, витрины метрик и данные для дашбордов. |
| `reporting-service` | Экспорт отчётов в PDF и XLSX. |
| `notification-service` | Уведомления о назначениях, сроках и результатах. |

Каждый сервис владеет собственной БД. Обмен между сервисами выполняется через версионируемые HTTP/gRPC-контракты из `contracts/` и доменные события брокера сообщений. Прямой доступ к чужим БД запрещён.

## Локальный запуск

```bash
docker compose up --build
```

API Gateway будет доступен на `http://localhost:8000`, документация — на `http://localhost:8000/docs`.

## Добавление бизнес-функции

1. Определить владельца данных — один конкретный сервис.
2. Добавить use case в `application/`, правила в `domain/`, адаптеры в `infrastructure/`.
3. Описать внешний API или событие в `contracts/` с новой версией.
4. Добавить unit-, integration- и contract-тесты.
